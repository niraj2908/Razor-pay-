# Judging Matrix

Every row points at code, tests, or database evidence in this repository. Where
something is implemented but not yet demonstrated end-to-end on real Razorpay
data, the row says so — an honest gap is more useful than an unbacked claim.

Verified 2 September 2026: 686 unit tests passing,
150 integration tests passing against a real database and real Razorpay Test
Mode, clean `lint`, `typecheck` and `build`, valid Prisma schema with the
database up to date on 12 migrations, production deployment live at
https://revenue-recovery-intelligence.vercel.app.

## Open gaps

These are real and stated deliberately:

1. Real ACT end to end is now verified, but **no revenue has been recovered by
   it**. The Payment Link the execution created is unpaid, so the outcome is
   `PENDING`, attribution is null, and no recovered amount exists. Executing a
   recovery and recovering revenue are different claims, and only the first is
   evidenced.
2. RETRY is priced by the models but is not performable — Razorpay has no
   retry-a-failed-payment API. The engine reports its expected value and
   selects the best executable strategy instead
   ([`executableStrategies.ts`](apps/web/src/lib/recovery/executableStrategies.ts)),
   so no decision can name an action the product cannot carry out; genuine
   retry recovery would need saved-token or subscription access.
3. Recovery probabilities are hand-set baselines, advisory only — not trained
   models — so which diagnosis leads to ACT is a calibration choice rather than
   a learned one.
4. Causal measurement has been exercised on synthetic Demo Workspace data; the
   real Test Mode merchant has three lifecycles, far too few to measure
   anything.
5. This is a prototype, not a certified payments product: no RBI authorisation,
   no PCI-DSS certification, no DPDP compliance attestation.
